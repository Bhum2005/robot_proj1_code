# ระบบเว็บของหุ่นกวาดขยะ + ระบบจดมิเตอร์หอพัก

เว็บสามหน้าที่ทำงานร่วมกัน รันคนละเครื่อง

```
   Raspberry Pi 5 (บนหุ่น)              เครื่องที่เปิดตลอด (โน้ตบุ๊ก/VPS)
   ┌──────────────────────┐            ┌──────────────────────────┐
   │ pi/server.py         │  pi/push.py│ hub/hub.py + pages.py    │
   │  หน้าคุมหุ่น           │ ─────────▶ │  เว็บลูกบ้าน   /          │
   │  กล้อง จอย เซอร์เรียล   │  ทุก 20 วิ │  เว็บเจ้าของหอ /owner     │
   │  :9000               │            │  ส่งต่อหน้าคุมหุ่น          │
   └──────────────────────┘            │  :8080                   │
            │ USB                      └──────────────────────────┘
      ESP32-S3 (เฟิร์มแวร์ esp32/main.cpp)
```

Pi ดับก็ยังเปิดเว็บดูรูปเก่าได้ทั้งหมด เพราะรูปถูกส่งออกมาเก็บไว้ตั้งแต่ตอนที่ยังเปิด

## โครงสร้างโฟลเดอร์

```
.
├── pi/                     ── รันบน Raspberry Pi 5 (บนหุ่น) ──
│   ├── server.py           หน้าคุมหุ่น :9000 · กล้อง (H.264/WebRTC + JPEG) · จอย · serial ไป ESP32
│   ├── push.py             ส่งรูป/ข้อมูลไป hub ทุก 20 วิ ทนเน็ตหลุด ไม่แย่งท่อภาพสด
│   ├── meter_ai/           AI อ่านเลขมิเตอร์ (OpenCV + โมเดล ONNX) — server.py เรียกใช้เอง
│   ├── systemd/            robot-server.service · robot-push.service
│   └── webrtc/             MediaMTX (วิดีโอ WebRTC) + สคริปต์ติดตั้ง setup_webrtc.sh
│
├── hub/                    ── รันบนเครื่องที่เปิดตลอด (โน้ตบุ๊ก) ──
│   ├── hub.py              เว็บหอพัก :8080 · เก็บรูป · ห้อง/บัญชี · ส่งต่อหน้าคุมหุ่น
│   ├── pages.py            หน้าเว็บ (ลูกหอ / เจ้าของหอ / เข้าสู่ระบบ) — แก้หน้าตาที่นี่
│   ├── make_demo.py        สร้างเว็บเดโมข้อมูลสมมุติ
│   └── systemd/            meterhub.service
│
├── esp32/                  ── เฟิร์มแวร์ ESP32-S3 (ล้อ แปรง แขนกล้อง) ──
│   └── main.cpp            v9: หยุดฉุกเฉิน X · ดับแปรงเมื่อขาดการติดต่อ Pi
│
├── ai-training/            ── เทรนโมเดลอ่านเลขใหม่ (รันบน PC ไม่ใช่บน Pi) ──
│
├── tests/                  ── ชุดทดสอบ (ไม่ต้องมีหุ่นจริง มีกล้อง/จอย/serial จำลองใน tests/stub) ──
│
└── docs/
    ├── install.html        คู่มือติดตั้งตั้งแต่ศูนย์ (เปิดในเบราว์เซอร์)
    ├── webrtc_install.html ติดตั้งวิดีโอ WebRTC
    ├── flowcharts/         ผังการทำงานทั้งระบบ 11 ผัง (flowcharts.pdf) + gen.py ที่ใช้วาด
    └── notes/              บันทึกการพัฒนา บั๊กที่เคยเจอ และค่าที่ติดตั้งจริง (ปิดข้อมูลส่วนตัวแล้ว)
```

| ทำงานที่ | ไฟล์ที่ต้องคัดลอกไป |
|---|---|
| Pi `/home/pi/server/` | `pi/server.py` `pi/push.py` และโฟลเดอร์ `pi/meter_ai/` |
| Pi `/etc/systemd/system/` | `pi/systemd/*.service` (แก้รหัส/โทเคน/IP ก่อน) |
| โน้ตบุ๊ก `~/meterhub-app/` | `hub/hub.py` `hub/pages.py` (ต้องอยู่โฟลเดอร์เดียวกัน) |
| โน้ตบุ๊ก `/etc/systemd/system/` | `hub/systemd/meterhub.service` |
| ESP32-S3 | แฟลช `esp32/main.cpp` ด้วย Arduino IDE / PlatformIO |

เฟิร์มแวร์ ESP32 **ต้องเป็น v9 ขึ้นไป** ที่มีคำสั่ง `X`
(หยุดฉุกเฉิน ล้อ + แปรงพร้อมกัน) ไม่งั้นปุ่มหยุดจะดับแค่ล้อ แปรงยังหมุนอยู่
เช็ครุ่นได้โดยส่ง `?` ทาง serial ต้องตอบ `# robot fw v9 ...`

### ระบบจดมิเตอร์ทำงานยังไง (ย่อ)

1. กดถ่ายบนหน้าคุมหุ่น / ปุ่ม R บนจอย → รูปเต็มเซนเซอร์ + ไฟล์ข้อมูลคู่รูป (ห้อง ชนิด เวลา)
2. AI อ่านเลขเบื้องหลัง จด "สิ่งที่เดา" ลงไฟล์ข้อมูล (ยังไม่ใช่ค่าจริง)
3. push.py ส่งรูปไป hub · ทีหลังถ้าข้อมูลเปลี่ยนส่งเฉพาะข้อมูล (/push-meta) ไม่ส่งรูปซ้ำ
4. หน้าเจ้าของหอโชว์ "AI อ่านได้" บนการ์ดรูป → กดยืนยันเป็นน้ำ/ไฟ (หรือพิมพ์เอง) → ขึ้นเป็นค่าของเดือน
5. ลูกหอเห็นเฉพาะค่าที่ยืนยันแล้ว + หน่วยที่ใช้ (เดือนนี้ − เดือนก่อน)

รายละเอียดทุกขั้นดูผังใน `docs/flowcharts/flowcharts.pdf`

## รันทดสอบก่อนเสมอ

ทั้งสองชุดรันได้โดยไม่ต้องมีหุ่นจริง เพราะมีกล้องจำลองให้

**ทางลัด — คำสั่งเดียวจบ** (สร้างโฟลเดอร์ชั่วคราวใหม่ เปิดเซิร์ฟเวอร์ รันทั้งสองชุด แล้วปิดให้เอง)

```bash
bash tests/run_all.sh
```

ถ้าจะรันเองทีละขั้น (hubtest ต้องใช้ `--dir` ใหม่ที่ว่างเปล่าทุกครั้ง):

```bash
# เตรียม
mkdir -p ~/t_photos
python3 hub/hub.py --dir ~/t_hub --owner-pw testowner123

# เปิดสองตัวนี้ค้างไว้คนละหน้าต่าง
PYTHONPATH=tests/stub python3 pi/server.py --port 9340 --photos ~/t_photos
HUB_TOKEN=tok-test python3 hub/hub.py --port 8250 --dir ~/t_hub --robot http://127.0.0.1:9340

# แล้วรันทดสอบ
python3 tests/regress.py       # 15 ข้อ — เส้นทางที่เคยพัง (ถ้า --photos ไม่ใช่ ~/t_photos ให้ตั้ง TEST_PHOTOS=<โฟลเดอร์>)
python3 tests/hubtest.py http://127.0.0.1:8250 ~/t_hub   # 29 ข้อ — API และสิทธิ์
```

`tests/regress.py` ครอบคลุมบั๊กที่เคยเกิดขึ้นจริงทั้งหมด ไม่ใช่เคสที่คิดขึ้นเอง
ถ้าแก้โค้ดแล้วชุดนี้ตก แปลว่าทำบั๊กเก่ากลับมา

## ติดตั้งใช้งานจริง

เปิด `docs/install.html` ในเบราว์เซอร์ มีครบตั้งแต่ศูนย์ แยกตามเครื่อง
พร้อมรายการตรวจ 11 ข้อก่อนแจกรหัสให้ลูกบ้าน

ย่อ ๆ

```bash
# เครื่องที่เปิดตลอด
HUB_TOKEN=<โทเคน> python3 hub/hub.py --port 8080 --dir ~/meterhub \
    --owner-path /ทางเข้าลับ --robot http://<pi>:9000 --robot-pass <รหัสหน้าคุมหุ่น>

# บน Pi
python3 pi/server.py --port 9000 --photos ~/robot_photos \
    --stream-size 854x480 --stream-quality 60 --back-url http://<hub>:8080/ทางเข้าลับ
python3 pi/push.py --to http://<hub>:8080 --token <โทเคนเดียวกัน>
```

ค่าที่ต้องตรงกันข้ามเครื่องมีสองตัว พลาดบ่อยที่สุด

| ค่า | ฝั่ง hub | ฝั่ง Pi | ไม่ตรงแล้วเป็นยังไง |
|---|---|---|---|
| โทเคนส่งรูป | `HUB_TOKEN` | `--token` | ขึ้น `คลังปฏิเสธ (403)` |
| รหัสหน้าคุมหุ่น | `--robot-pass` | `ROBOT_PASS` | เปิดหน้าคุมหุ่นได้แต่ภาพไม่ขึ้น |

## ข้อมูลเก็บยังไง

```
~/meterhub/
  rooms.json              ห้องทั้งหมด รหัสเก็บเป็นแฮช PBKDF2 200k รอบ
  owner.json              รหัสเจ้าของหอ แฮชเหมือนกัน
  secret.key              กุญแจเซ็นคุกกี้ สิทธิ์ 600
  photos/101/2026-10/     รูปแยกห้อง แยกเดือน เปิดดูเองได้ตรง ๆ
  photos/_inbox/          รูปที่ยังไม่รู้ว่าห้องไหน
  thumbs/   meta/
```

ไม่มีฐานข้อมูล ตั้งใจให้กู้ง่าย ถ้าโปรแกรมพังในอนาคต รูปยังเรียงอยู่ในโฟลเดอร์ห้อง
ให้เปิดดูด้วยโปรแกรมดูรูปธรรมดาได้ ย้ายเครื่องก็แค่คัดลอกโฟลเดอร์นี้ไปวาง

สำรองข้อมูล = คัดลอก `~/meterhub` ทั้งโฟลเดอร์ เท่านั้นพอ
