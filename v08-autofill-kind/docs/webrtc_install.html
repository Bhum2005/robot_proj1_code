ติดตั้งวิดีโอ WebRTC ให้หน้าคุมหุ่น

ทำให้ภาพสดเป็นวิดีโอ H.264 ที่ส่งทาง UDP ใช้เน็ตน้อยและไม่ค้างตอนหุ่นอยู่ไกล การขับ ซูม โฟกัส และถ่ายภาพ 64MP ใช้ได้เหมือนเดิมทุกอย่าง ถ้ามีปัญหา ย้อนกลับได้ในคำสั่งเดียว (ขั้นที่ 9)

ใช้เวลา ราว 15–20 นาที · ต้องมี โน้ตบุ๊ก + หุ่นต่อ hotspot ตัวเดียวกัน และ Pi ออกอินเทอร์เน็ตได้ · ป้ายสีมุมขวาของแต่ละขั้น บอกว่าพิมพ์ที่เครื่องไหน: โน้ตบุ๊ก prompt เป็น bhum@bhum-loptop, Pi prompt เป็น pi@raspberrypi

0เช็คลิสต์ก่อนเริ่ม

1เช็คไฟล์ว่าถูกตัว โน้ตบุ๊ก

bhum@bhum-loptop
cd ~/Downloads
md5sum server.py setup_webrtc.sh mediamtx.yml mediamtx.service
ต้องได้ตรงทุกบรรทัด: 
fa0d4a93b706a099960bcca63b88e44c  server.py
69a059d5bdbf8cb8bab2ee90e086d715  setup_webrtc.sh
6dc76d104725f47c25b62dba65ca0751  mediamtx.yml
f09644fef92b28b23ce2cdbcfebf71f7  mediamtx.service
ไม่ตรง หรือขึ้น No such file → เบราว์เซอร์อาจตั้งชื่อเป็น server(1).py ดูด้วย ls -lt ~/Downloads | head แล้วเปลี่ยนชื่อตัวที่ md5 ตรงให้เป็นชื่อปกติ เช่น mv "server(1).py" server.py

2สำรองตัวเดิม แล้วส่งไฟล์ขึ้น Pi โน้ตบุ๊ก

bhum@bhum-loptop
ssh pi@raspberrypi.local "cp ~/server/server.py ~/server/server.py.bak-webrtc"
scp server.py setup_webrtc.sh mediamtx.yml mediamtx.service pi@raspberrypi.local:/home/pi/server/
ไม่มี error = ผ่าน (scp จะโชว์ชื่อไฟล์ทั้ง 4 พร้อม 100%)
Could not resolve hostname raspberrypi.local → ใช้ IP ของ Tailscale แทน: เปลี่ยน pi@raspberrypi.local เป็น pi@IP-Tailscale-ของ-Pi ทั้งสองบรรทัด

3เข้า Pi โน้ตบุ๊ก

bhum@bhum-loptop
ssh pi@raspberrypi.local
prompt ต้องเปลี่ยนเป็น pi@raspberrypi:~ $ ตั้งแต่ขั้นนี้ไปพิมพ์ในหน้าต่างนี้

4เช็คไฟล์บน Pi แล้วรันสคริปต์ติดตั้ง Pi

pi@raspberrypi
cd ~/server
md5sum server.py
bash setup_webrtc.sh

สคริปต์ทำสามอย่าง: ลง python3-av, ดาวน์โหลด MediaMTX v1.9.3 มาติดตั้งเป็น service, แล้วรีสตาร์ทหุ่น ใช้เวลา 1–3 นาที อาจถามรหัส sudo ของ Pi ระหว่างนั้นหน้าคุมหุ่นจะหลุดไปราว 20 วินาที

บรรทัดแรกต้องได้ fa0d4a93b706a099960bcca63b88e44c server.py และท้ายสุดควรเห็นประมาณนี้: 
==> 1/3 ลง python3-av + เช็ค picamera2
    picamera2 รองรับวิดีโอ H.264 แล้ว
==> 2/3 ลง MediaMTX v1.9.3 (linux_arm64v8)
==> 3/3 ให้ robot-server เปิดหลัง MediaMTX

MediaMTX: ทำงานอยู่
... camera: วิดีโอ H.264 1280x720 2000kbit/s -> rtsp://127.0.0.1:8554/robot (ส่งอยู่)

6ลองในเบราว์เซอร์ (วงเดียวกัน) โน้ตบุ๊ก

  1. เปิด http://raspberrypi.local:9000/ แล้วกด Ctrl+Shift+R (บังคับโหลดหน้าใหม่)
  2. กด ตั้งค่า → คุณภาพสตรีม ดูแถว "ภาพสดวิ่งทาง" ต้องขึ้น WebRTC (วิดีโอ H.264)
    2–5 วิแรกจะเห็น JPEG ก่อน แล้วสลับเป็นวิดีโอเอง
  3. ลองขับ หันแขน ซูม กดโฟกัส ต้องใช้ได้เหมือนเดิม
  4. ลองกดถ่ายรูป ภาพสดจะหยุด 1–3 วิ สลับเป็น JPEG แวบหนึ่ง แล้วกลับเป็นวิดีโอเอง อาการนี้ปกติ
ถ้าแถวนั้นขึ้น WebSocket · วิดีโอ: <ข้อความ> ข้อความหลังคำว่า "วิดีโอ:" คือเหตุผลที่เปิดไม่ได้ ให้ส่งให้ Claude ระหว่างนั้นหุ่นใช้ JPEG ได้ตามปกติ

7ทดสอบของจริง: ขับออกไปไกล

ขับไปจุดที่เมื่อวานภาพค้าง สิ่งที่ควรเห็นคือ ภาพอาจแตกเป็นบล็อกแวบหนึ่งแล้วชัดกลับมาภายในราว 1 วิ แต่ไม่ค้างนิ่งนาน และไม่ขึ้น "สายหลุด"

ถ้ายังสะดุด ลดบิตเรตเหลือ 1000 kbit/s (ภาพยังชัดใกล้เคียงเดิม):

pi@raspberrypi
sudo mkdir -p /etc/systemd/system/robot-server.service.d
printf '[Service]\nEnvironment=ROBOT_H264_KBPS=1000\n' | sudo tee /etc/systemd/system/robot-server.service.d/h264.conf
sudo systemctl daemon-reload && sudo systemctl restart robot-server

กลับไปค่าเดิม: sudo rm /etc/systemd/system/robot-server.service.d/h264.conf && sudo systemctl daemon-reload && sudo systemctl restart robot-server

ดูว่าซีพียูไหวไหม (ทางเลือก)

pi@raspberrypi
top -d 2

ดูแถว python3 (คือ server.py) ช่อง %CPU ไม่เกิน ~100 (หนึ่งคอร์) ถือว่าสบาย กด q เพื่อออก อุณหภูมิดูได้ในหน้าสถานะของหุ่น ควรต่ำกว่า 75°C

8ลองผ่านหน้าเจ้าของหอ

  • เครื่องที่เปิดแอป Tailscale (โน้ตบุ๊ก หรือมือถือที่ลงแอปแล้ว): http://IP-Tailscale-ของ-laptop:8080/ทางลับ-ตั้งเอง → ล็อกอิน → คุมหุ่น ต้องได้วิดีโอเหมือนขั้นที่ 6
  • ผ่าน Funnel (https://bhum-loptop..ts.net/...) จะได้ภาพ JPEG แทน เพราะวิดีโอต้องใช้ UDP ซึ่ง Funnel ไม่รองรับ อาการนี้เป็นไปตามที่ออกแบบไว้

9ถ้ามีปัญหา: ย้อนกลับ Pi

ก. ปิดวิดีโออย่างเดียว (แนะนำลองอันนี้ก่อน)

กล้องกลับไปตั้งค่าแบบสตรีมเดียว ภาพสดเป็น JPEG ทาง WebSocket เหมือนเมื่อวานทุกอย่าง

pi@raspberrypi
printf '[Service]\nEnvironment=ROBOT_WEBRTC=off\n' | sudo tee /etc/systemd/system/robot-server.service.d/webrtc-off.conf
sudo systemctl disable --now mediamtx
sudo systemctl daemon-reload && sudo systemctl restart robot-server

เปิดกลับ: sudo rm /etc/systemd/system/robot-server.service.d/webrtc-off.conf && sudo systemctl enable --now mediamtx && sudo systemctl daemon-reload && sudo systemctl restart robot-server

ข. กลับไปใช้ server.py ตัวก่อนหน้าทั้งไฟล์

pi@raspberrypi
cp ~/server/server.py.bak-webrtc ~/server/server.py
sudo systemctl restart robot-server

10ส่งผลให้ Claude

ทำถึงขั้นไหนแล้วเจออะไร ให้คัดลอกข้อความจากหน้าจอส่งมา สิ่งที่ช่วยได้มากที่สุดคือ

  • ผลจากขั้นที่ 4 (ทั้งหน้าจอ ตั้งแต่ ==> 1/3 ถึงบรรทัดสุดท้าย)
  • ข้อความในแถว "ภาพสดวิ่งทาง" จากขั้นที่ 6
  • ความรู้สึกตอนขับไกลในขั้นที่ 7 (ลื่นขึ้นไหม ยังค้างไหม)
